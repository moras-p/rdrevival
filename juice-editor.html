Horizontal & jump input

Ladder top-entry tolerance adds pixels to each side of the existing grounded DOWN alignment window on RDX ladders. 0 preserves the previous entry window; 1 adds 1 px left and right. DOWN+LEFT/RIGHT still crawls past the ladder.

Jump release is the percentage of upward velocity retained when jump is released early. Lower values produce a shorter tap-jump.

Air & surface corrections

1. Start with the default A/B

A is deliberately raw: the same xrick frame with editor juice disabled. B is editable: every recipe, template and numeric control in the inspector changes B only. Both panes use the same input, player state, enemies, bullets, dynamite and game frame.

  1. Choose Classic for Classic map flags, or load the RDX ROM and choose RDX to project the live RDX descriptors through the same xrick 8×8 solver.
  2. Choose a level and click the preview so keyboard controls are captured.
  3. Use the A/B · A · B preview switch to play both synchronized presentations together or give either view the full preview area.
  4. Open Recipe & actions when you need to choose a whole-game template or a different event; collapse it again to return space to the preview.
  5. Use the Action feedback bundle window to apply a recipe or tune individual pieces. Any main window can be collapsed or expanded for focused editing.
  6. Play normally and compare A against B at the same instant.

2. Accept a new baseline

When B is clearly better, press Accept B as new A baseline. A becomes a frozen copy of B's current juice profile. Further edits continue on B, so the next comparison becomes “accepted version” versus “new experiment”.

Use Reset A to JUICE OFF at any time to return to the original raw-game reference. Accepting does not alter xrick gameplay or production defaults.

3. Actions, recipes and pieces

The Recipe & actions window chooses the event being tuned. Whole-game templates apply a complete low-end style to every B action at once; Action recipes then set a coherent group of effects for one action. Each effect card exposes a piece template plus raw parameters for fine tuning.

Wall hug / falling contact fires at a low cadence when xrick is falling, the player presses into a wall, and xrick's normal horizontal step is blocked. Projectile near miss fires once when an active hostile projectile sweeps close to Rick's head without overlapping him; proximity controls magnitude and the event carries left/right pan for a cheap fly-by cue. Target hit is confirmed from the enemy's actual death transition at the bullet's leading collision point.

Particles
Pooled dust, sparks, debris and bursts.
Camera impulse
Short screen kick/shake; no extra render pass.
Contact flash (area)
Cheap single-rectangle emphasis at the event point.
Target sprite flash
White or red target-silhouette flash for a chosen number of 25 Hz frames. For a confirmed bullet hit the target is the enemy, not Rick.
Foreground block flash
Old-school 8px block/ripple flash around blasts. In RDX presentation it uses semantic presentation-layer masks, so a recipe can light backdrop and decorative foreground while preserving walkable Midground and actor sprites instead of becoming a modern full-screen post-process.
Stop-the-world / freeze-frame
B holds the exact impact frame for N xrick frames while A continues, so the A/B comparison stays deterministic. The same value maps to a true global simulation hold when promoted into the production game.
Actor displacement / squash
Takeoff, recoil and landing deformation using the real actor sprite. Terrain is never part of the transform.
Hit knockback
Independent enemy/hero push-back after projectile or dynamite damage. It is a bounded sprite/blitter displacement in the editor so A/B remains one deterministic gameplay simulation.
HUD inventory feedback
Flash/fade/jitter the next bullet or dynamite token when a resource is consumed. It targets the same 8px icon cadence now used by both Classic and RDX HUDs.
Audible effect layer
Optional Game Juice sample/category layer using the same live gameplay-window JuiceRuntime path. Native Amiga game SFX continue underneath, so the edited layer can reinforce or reshape existing cues without replacing the core mixer.

4. What “live xrick” means

The editor is not a substitute platformer. The production browser xrick simulation remains authoritative for movement, collision, enemies, bullets, dynamite and animation state. Presentation changes the terrain provider, not Rick's solver: Classic reads Classic flags and RDX projects live MT/ML descriptors into the same 8×8 xrick semantics.

Invincible traversal and Infinite ammo/dynamite are editor conveniences for repeated testing; turn them off when validating normal game constraints.

5. Gameplay feel controls

Coyote time is measured in fixed 25 Hz gameplay frames and applies to both Classic and RDX movement. It retains jump eligibility briefly after support is lost without restoring a fake grounded state or snapping Rick back to the ledge.

Fall bounce min height is the minimum tracked drop distance before the native RDX long-fall rebound may trigger. The existing impact-speed gate still applies, so lowering this value does not make tiny low-speed steps bounce. These two controls affect the one shared gameplay simulation and are intentionally not A/B-specific juice pieces.

6. Performance budget

The default target is intentionally conservative for low-end platforms. Watch B juice first: it is the measured editor-side cost of the editable feedback pass. The adaptive budget can reduce particle density when the selected target is exceeded.

Bundled templates are intended to stay CD32 ✓: opaque palette/tile flashes and 1:1 sprite/blitter displacement are preferred, particles are small bounded opaque lists, camera offsets are integer-friendly, and optional accent voices are capped. Manual settings remain deliberately broader for comparison, but alpha blending or real-time sprite scaling are labelled ENHANCED ⚠ and must not be promoted into Revival presets. The recommended Amiga/CD32 master preset is intentionally flash-heavy and particle-light.

Use Run B benchmark after a meaningful change, especially for explosions and stacked hit feedback.

7. High-quality Amiga sound

The production native Amiga sound engine stays active in the editor. Default is HIGH · native Amiga MAX with the A500 filter and Headphones spatial mode. Switch to STANDARD or LOW directly here when profiling slower targets.

Audible Effects are live in the gameplay windows. B is enabled by default, so sample choice, category overrides, ADSR, filtering, pitch/rate, panning and layers edited in Audible Effects use the same JuiceRuntime audio path while you play. For the selected Audible Effects action, the corresponding native logical SFX is suppressed while B live routing is active, preventing a doubled sound; choose Off to hear native audio only.

8. Saving and exporting

B is autosaved locally as a temporary draft. Save B draft now forces an immediate local checkpoint. Export B JSON exports the editable juice profile for review; it does not promote the profile into production settings.

A/B baseline state is local editor workflow state. If you accept B into A, that gives you a frozen comparison target while continuing to tune B.

9. Keyboard controls

Click inside the preview first. Use ←/→ to move, Z or ↑ to jump, X for the real gun action, C for the real dynamite action, ↓ to crawl and Space for raw Fire. A and B never receive separate controls because they are two presentations of the same simulation.
